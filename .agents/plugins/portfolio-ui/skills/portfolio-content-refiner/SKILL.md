# Portfolio Content Refiner & Impact Polisher Skill

Use this workflow to elevate copy across the portfolio, ensuring every experience, project bullet, and bio statement clearly conveys technical depth and measurable business value.

## 1. High-Impact Phrasing: Google's "XYZ" Formula

When describing projects or work experience, rewrite entries using:
> **"Accomplished [X] as measured by [Y], by doing [Z]"**

### Examples:
- **Weak**: "Built a chatbot for doctors to search clinical data."
- **Strong (XYZ)**: "Architected an autonomous 8-agent LangGraph system executing within an 8 GB GPU VRAM footprint, reducing clinical query resolution time while ensuring zero patient data leakage with OMOP CDM validation."

- **Weak**: "Worked on predictive models for loan default prediction."
- **Strong (XYZ)**: "Engineered an end-to-end credit risk pipeline across 2.9M+ records using XGBoost and LightGBM, boosting ROC-AUC by 14% and deploying model interpretability via SHAP."

## 2. Copy Review Framework

### A. Tone & Positioning
- **Primary Persona**: Final-year NUS Business Analytics student specializing in Machine Learning, Multi-Agent AI systems, and predictive modeling.
- **Tone**: Analytical, proactive, confident, and metrics-driven. Avoid hollow buzzwords; highlight concrete architectural decisions (e.g. LangGraph, FAISS, Ollama, DuckDB, LRU caching).

### B. Experience & Project Consistency
Whenever updating `index.html` or case study files:
1. Verify job title, company name, and date formats match `files/Lee Wei Kiat Resume.pdf`.
2. Ensure skill tags in each project card directly mirror the technologies highlighted in the text.
3. Check that metrics are realistic, defensible, and specific (e.g., GPA 4.78/5.0, #1/77 in Web Mining, 2.9M+ records).

---

## 3. Review Checklist for New Content
- [ ] Every bullet starts with a strong action verb (Architected, Engineered, Developed, Deployed, Benchmarked).
- [ ] Contains at least one concrete metric (% improvement, volume of data, latency reduction, accuracy/AUC gain, memory limit).
- [ ] Explicitly specifies tools and libraries used rather than generic terms (e.g. "PyTorch and HuggingFace Transformers" instead of just "deep learning").
- [ ] Grammar and punctuation are flawless with consistent hyphenation and capitalization (e.g. "JavaScript", "PyTorch", "LangGraph").
